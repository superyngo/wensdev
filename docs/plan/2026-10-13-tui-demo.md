# TUI demo project plan: wens-tui-lab
Status: Shipped (2026-10-14)

A demo project with no real functionality, built on ratatui 0.30 + crossterm 0.29 (cached
locally), that puts the `tui-components` skill into practice. Every new pattern it needs goes
back into the skill (`skills/tui-components`). Repo:
[wens-tui-lab](https://github.com/superyngo/wens-tui-lab).

## Assessment and order

1. **Tiling workspace** (first): binary split tree (`src/layout.rs` `Node`/`TileLayout`,
   `collect_splits`/`set_ratio_at`, a ratio per split). Dragging a divider = hit-map target
   `Divider(path)` + a drag state. A popup "Layout" dialog picks a preset (1 / 2 columns / 2 rows /
   1+2 / 2x2 / 3 columns, like omarchy/VS Code) or splits the focused pane. Medium difficulty. It
   reuses the existing modal + menu specs, and the split tree also underlies option 2's snapping.
2. **Desktop windows** (second): free-floating windows, z-order `Vec` (last = top), drag on the
   title bar moves a window, drag on an edge or corner resizes it. A hidden snap grid (for
   example 1/2, 1/3, 1/4 of the screen) snaps positions and sizes. Overlapping windows rely on the
   hit map's "last pushed wins" rule plus painting from bottom to top. Taskbar +
   minimize/maximize. Higher difficulty: clipping, resize minimums, and a window dragged
   off-screen.
3. **Right-click context menu** (both modes): target enum = `Pane(id)` / `Divider(path)` /
   `Window(id)` / `TitleBar(id)` / `Desktop` / `Taskbar`. Items are derived from the target
   (menu-dropdown spec).

## Structure

- One repo, one binary, mode switch: `wens-tui-lab tile` / `wens-tui-lab desk` (or F1/F2 at
  runtime). Modules: `hitmap`, `theme`, `menu`, `dialog`, `tile/`, `desk/`.
- Tests: geometry unit tests, plus `TestBackend` + clicking the hit map (contracts C10).
  Real-artifact check at 80x24, at minimum size, and with fullwidth labels.

## New skill content (written back while developing)

- `components/split-panes.md` (split tree, divider hit, drag, ratio clamping, min size, preset
  layouts)
- `components/floating-windows.md` (z-order, move/resize drag, snap grid, focus raise, clipping)
- `contracts.md` new C11 "Drag sessions" (press → capture → drag → release, keep ownership even
  when the pointer leaves the rect, Esc cancels and restores)
- `catalog.md` / SKILL index: "Split / resizable panes" Mapped → Specified, plus new
  floating-window and taskbar rows
- Context menu: add a "target-derived items + right-click retargeting" example to
  menu-dropdown.md

## Findings folded into the skill

- menu-dropdown.md Render step 4 said push the menu body rect *last*; with C2's last-wins
  `HitMap::hit` that shadows every row. Body must be pushed *first* (rows after). Same for
  dialogs: push the dialog body before its buttons/rows.
- A divider/handle hit target should carry the frame geometry (`Target::Divider(Divider)`), so a
  drag session starts from what the user saw instead of re-running layout in the input handler.
